Gates the effects/triapi/decal cluster of the 2026-06-29 M2c self-draw-primitives
architecture (`csoz docs/plans/2026-06-29-m2c-selfdraw-primitives-architecture.md`

cluster (C-DEC / C-TRI / C-SHIM) is cleared to proceed.**

## S1 — interface proof  ✅ (retires risk-table R1 "R_DecalSetupVerts availability")

Pinned FWGS build (Xash3D-FWGS 0.21, 4087, b2a5f0d), GL 4.6 NVIDIA.

- `gRenderAPI.R_DecalSetupVerts` = **NON-NULL**; `DrawSingleDecal`,
  `R_EntityRemoveDecals` also non-null. (Also statically guaranteed: the
  handshake audit in `csz_render_iface.cpp` FATALs on a null `R_DecalSetupVerts`,
  and it is not whitelisted — the game cannot start past handshake if it is null.)
- `surf->pdecals` chain (EngSurface mirror, `core/csz_engine_bsp.h:159`) **walks
  cleanly**. Following only `pnext` (engine `decal_t` first field, offset 0) is
  ABI-safe. Live scan: `surfWithDecals=1 totalDecals=4 → 11 → 13` accumulating as
  the host shot a wall.
- Live `R_DecalSetupVerts(decal, surf, surfTexSlot, &count)` call returned
  **count = 4** with a **verified vertex layout** — interleaved `float[7]` per
  vertex = **pos.xyz · base-uv · lightmap-uv** (stride 7). Captured verts:

  ```
  v[0] pos=(417.92 2389.45 -128.00) base-uv=(1.0000 0.0000) lm-uv=(0.3877 0.3606)
  v[1] pos=(417.92 2373.45 -128.00) base-uv=(1.0000 1.0000) lm-uv=(0.3877 0.3684)
  v[2] pos=(401.92 2373.45 -128.00) base-uv=(0.0000 1.0000) lm-uv=(0.3798 0.3684)
  ```

  Sanity: a 16-unit decal quad on a z=-128 surface; base-uv is a clean unit
  quad; lm-uv sits in the [0,1] atlas range. The stride-7 hypothesis is
  CONFIRMED — this is exactly the geometry decision A (`csz_decal` self-draw +
  lightmap-UV reuse, 坑22) needs. (The `texture` arg passed is the surface's gl
  texture slot, a valid ref texturenum; the engine uses it only to scale decal
  UVs, so the real decal texture's UV scale would differ — irrelevant to the
  layout question, noted for C-DEC.)
- **efx shim (decision C)**: swapping `gEngfuncs.pEfxAPI` to a by-value copy with
  18 wrapped emitters installs + restores cleanly (no crash, lifecycle logged).
  Live intercept proven — FIRST-HIT on `R_BulletImpactParticles`, `R_DecalShoot`,
  `R_StreakSplash` from the client's own emit sites. The swap mechanism, the A/B
  toggle, and transparent passthrough all work. → C-SHIM GO.

## S2 — TriAPI boundary  ✅

Runtime: `pTriAPI ver=1`, **all 19 members non-null** (RenderMode, Begin, End,
Color4f, Color4ub, TexCoord2f, Vertex3fv, Vertex3f, Brightness, CullFace,
SpriteTexture, WorldToScreen, Fog, ScreenToWorld, GetMatrix, BoxInPVS,
LightAtPoint, Color4fRendermode, FogParams). The `csz_triapi` mirror has the
full surface available.

Consumer classification (`grep pTriAPI-> cl_dll`), by domain:

| Consumer | calls | Domain | Owner under takeover |
|---|---|---|---|
| `particleman/CBaseParticle.cpp` | 8 | **3D world** (flows through `HUD_DrawTransparentTriangles` → `g_pParticleMan->Update`) | **OURS** — dispatch swaps `pTriAPI`→`csz_triapi` around the call |
| `hud_spectator.cpp` | 45 | **3D world** overview map (`HUD_DrawNormalTriangles`) + some 2D insets | **OURS** for the 3D overview; the 2D inset borders stay engine-2D |
| `StudioModelRenderer.cpp` | 4 | engine studio renderer chrome | **DEAD under takeover** — `csz_studio` replaces the engine studio renderer, so these are never invoked |
| `ammo.cpp` | 5 | **2D HUD** ammo bar | engine 2D (`HUD_Redraw`, outside our frame) — NOT swapped |
| `draw_util.cpp` | 5 | **2D HUD** fill helper | engine 2D — NOT swapped |
| `hud/sniperscope.cpp` | 4 | **2D HUD** scope overlay | engine 2D — NOT swapped |
| `hud/radar.cpp` | 3 | **2D HUD** radar | engine 2D — NOT swapped |
| `hud/spectator_gui.cpp` | 5 | **2D HUD** spectator GUI | engine 2D — NOT swapped |

Conclusion: our dispatch owns ONLY the two 3D-world entry points
(`HUD_DrawNormalTriangles` = spectator overview, `HUD_DrawTransparentTriangles` =
particleman/environment). The 2D HUD consumers run in the engine's own 2D pass
AFTER our `RenderFrame` returns and must keep the engine's real `pTriAPI` — which
they do, since we swap only around the two 3D dispatch points and restore
immediately after each. `csz_triapi` must implement the full member set
(RenderMode/Begin/End/Color4*/TexCoord2f/Vertex3f*/Brightness/CullFace/
SpriteTexture/Fog/FogParams at minimum); WorldToScreen/ScreenToWorld/GetMatrix/
BoxInPVS/LightAtPoint are read-only queries the 3D consumers may call — provide
real implementations or safe stubs + a one-shot log (no silent no-op).

## S3 — efx scope calibration  ✅ (live, single-shooter sample)

Live per-second efx rate while the host fired its own rifle at walls
(`ev_cs16.cpp` CS16 combat path):

```
efx ~1s rate: R_StreakSplash=4 R_BulletImpactParticles=4 R_DecalShoot=4
efx ~1s rate: R_StreakSplash=7 R_BulletImpactParticles=7 R_DecalShoot=7
efx ~1s rate: R_StreakSplash=2 R_BulletImpactParticles=2 R_DecalShoot=2
```

Every world-bullet impact fires the **trio**: `R_BulletImpactParticles`
(dust puff) + `R_StreakSplash` (impact sparks) + `R_DecalShoot` (bullet hole,
which stays on the engine path per decision A). This is one shooter; 32-bot
crossfire scales this up linearly, so the impact trio is unambiguously the
high-frequency core.

**First-batch takeover list** (`csz_particle` / `csz_beam`), grounded in the
call-site grep (`ev_cs16.cpp` = active CS16 path, `ev_hldm.cpp` = HL weapons,
`entity.cpp` = generic events):

- `csz_particle` (decision C, high freq first): **R_BulletImpactParticles**,
  **R_StreakSplash** (CS16 impacts) → then `R_SparkEffect`/`R_SparkShower`
  (ricochet/metal), `R_RocketTrail` (rockets). tracer path (`R_TracerEffect`) as
  view-aligned quad.
- `csz_beam` (decision C): **R_BeamPoints / R_BeamEntPoint** first (gauss/gun
  beams in `ev_hldm.cpp`, + CSOZ zombie skills later); `R_Sprite_Trail`
  (egon/gauss balls) folds in as a beam/particle trail.
- Already covered elsewhere (wrapped only to COUNT, still passthrough):
  `R_DecalShoot` (engine decal path, decision A), `R_MuzzleFlash` (dlight,
  already mirrored via `CL_AllocDlight` registry).
- **OWED long tail**: every other `TE_*`/efx entry not in the first batch — the
  shim passes them through to the engine and logs once (not silently swallowed);
  under takeover the engine does not draw them, so they are registered
  not-yet-visible, NOT claimed complete.
